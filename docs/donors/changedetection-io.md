## Runtime boundary

`poc/dichiarazioni_pubbliche/changedetection_watch.py` is an opt-in local-API consumer. Run a separately licensed `changedetection.io` **0.60.9** service on the MiniPC, bound to loopback, with API token access enabled and persistent private storage. Before installing its image, verify the image digest and version correspond to the upstream release. There is no automatic installation, service activation or source registration in this change.

An operator must first approve a source as genuinely lacking a usable feed and register its exact HTTPS canonical URL, `changedetection.io` watch UUID, `source_id`, `locator_id` and `WEB_NO_FEED` family as an opt-in DP-515 policy. Derive `locator_id` with `changedetection_locator_id(watch_uuid, canonical_url)`, which produces `cdio:<uuid>:<sha256-of-exact-canonical-url>`. This pins URL and watch UUID in the stored DP-515 policy fingerprint: changing either requires fresh admission and rights/budget receipts; legacy `cdio:<uuid>` locators fail closed. No live source profiles have been admitted, so there is no existing authorized profile to migrate. Neither feed sources nor unregistered URLs are eligible. Authenticate the source-rights receipt, runtime capability receipt and DP-514 cost/budget receipt before setting readiness to READY. Keep API credentials in the MiniPC secret mechanism, never in the source registry or Git. The adapter only permits an HTTP API at `127.0.0.1` or `::1` and does not follow redirects.

The upstream service fetches only its explicitly registered, rights-authorized site; DP-515's `begin_poll` decides whether to read its **cached** local snapshots. Do not add the same URL to an RSS/source-poll fetcher or another DP scheduled source acquisition. The provider's check interval must remain bounded by the approved per-source fetch cadence and budget. Schedule DP-515 intake after the expected upstream check; its configured `max_check_age_seconds` (default 600) refuses old provider results, and a provider check must be newer than the previous successful DP observation before advancing freshness. The adapter never requests provider rechecks, starts a timer, calls the source URL, creates watches or dispatches child jobs. Existing DP-515 backoff, lease, state CAS, dedupe and private held child proposals remain authoritative. This keeps a single acquisition scheduler per source while DP schedules only its existing admission checks.

For each DP-515 admitted attempt, the adapter reads upstream watch metadata, history and latest normalized text snapshot, confirms the watch still points exactly to the approved URL, checks that the last provider check succeeded recently, hashes the snapshot, creates a `WatchObservation`, and commits it via `LocalSourceWatchStore`. Unchanged bytes reuse `sha256:<digest>` as the source version even if the provider creates a new history timestamp; changed bytes generate at most the ordinary one DP-515 private review proposal per work key. Errors map to unavailable attempts and source-local backoff. A revoked rights, capability or budget gate stops the provider read altogether. No external content becomes public without the existing review and publication gates.

`ChangedetectionReceipt` returns a private SHA-256 receipt binding the source, canonical URL, watch UUID, DP attempt ID, observation, provider history key, content hash and disposition. The DP-515 store durably holds the observation, gate readbacks, decision and private proposal; the caller should retain the returned provider receipt in its private operations evidence if a separate audit needs the upstream history key. Snapshot bodies and API keys must never be logged or persisted in this receipt. Its cost remains `None` (unknown) until the caller measures actual MiniPC consumption; free local software is not proof of zero cost.

## Acceptance and live hold

Synthetic-only validation: `PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=poc python3 -m unittest tests.test_changedetection_watch tests.test_dp515_incremental_watch tests.test_dp515_durable_watch_next tests.test_source_adapters -v`. The `test_smoke_synthetic_no_real_source_access` uses an in-memory SQLite fixture and synthetic snapshots; no real site or changedetection service is accessed. Verify the installed release, release digest, rights scope, approved no-feed URL, provider cadence, cost ceiling and API reachability before any live read. A live-source smoke and deployment remain **HOLD** until the owner has supplied that source and acquisition authorization; tests alone are not live acceptance.
