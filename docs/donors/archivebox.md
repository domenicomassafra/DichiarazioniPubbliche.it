## Activation and scope

The default capture contract remains `archive_adapter=None` and archives nothing. An operator must explicitly supply `ArchiveBoxArchiveAdapter` with an installed, isolated ArchiveBox v0.9.73 Python executable, a previously initialized private ArchiveBox collection under the private `CaptureBodyStore.root`, the same live `SourceFamilyUseGuard` used by `capture_content`, and `network_fetch_permitted=True` **only after owner source-use approval**. No package installation, service activation, real-source URL submission, remote media archiving or production modification is part of #171.

The pipeline requires acquisition permission plus `FETCH`, `STORE_BODY`, `PARSE_TEXT` and `ARCHIVE` where applicable. The adapter separately rejects non-HTML, held, missing or SHA-mismatched captures; checks the URL subject and private storage, and revalidates live `FETCH`, `STORE_BODY`, `PARSE_TEXT` and `ARCHIVE` both immediately before starting the donor process and after it returns. A mid-run revocation blocks the final receipt; outbound network isolation remains required to constrain requests while the donor is executing. A denied or revoked permit fails closed. The donor receives the reviewed original URL and may re-fetch it: its container/network namespace must deny private/metadata IP ranges, uncontrolled redirects and external media; permit only the owner-approved source hostname and allowed output methods. The adapter restricts ArchiveBox to depth 0, at most one URL, 4 MiB, 60-second crawl budget and the `readability` plugin. This configuration deliberately cannot claim the full WARC/PDF/media acceptance of #162.

The adapter runs a fixed `python -c` API script without a shell, through a distinct interpreter and initialized collection (mode `0700`). A per-URL-and-body-SHA ArchiveBox crawl tag provides durable retry deduplication; existing sealed crawls are read back, and running crawls return `PENDING`. Request/pending/completion events reuse the existing capture lifecycle. ArchiveBox keeps its own actual bytes in private storage. A sealed readability snapshot produces an immutable mode-`0600` content-addressed **receipt JSON** under `archivebox_receipts/`; the pipeline validates its digest and original capture SHA before accepting a `PRIVATE_ARCHIVEBOX` success. The receipt contains donor version/commit, archive crawl/snapshot IDs, original URL SHA, capture SHA, extractor, `publication_state=HOLD`, and a **private receipt locator**. This proof identifies an ArchiveBox-managed artifact, and does not copy the saved body or assert a public locator. No `archive_url` or public side effect is created. Pending snapshots stay pending; reconciliation and ArchiveBox collection retention need owner-approved runtime design. Source body retention follows existing private policy.

The bridge supplies ArchiveBox `PERMISSIONS=private` in the official `add()` configuration. It also checks the persisted crawl and every matching snapshot before accepting `PENDING` or `SUCCEEDED`; an existing public crawl or snapshot fails closed as `ARCHIVEBOX_DONOR_NOT_PRIVATE`. This is necessary even in a private filesystem: ArchiveBox's default permission for new crawls can be `public`, as the isolated WARC canary for #162 confirmed on 2026-10-23.

## Evidence and HOLD

On MiniPC worktree `DichiarazioniPubbliche.it-171`, the offline synthetic process fixture verifies request/pending/success/failure, retry, hash pinning, immutable private receipt, idempotence, denied/revoked source use, failed subprocess, timeout and unauthorized network fetch. Run:

```sh
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=poc python3 -m unittest tests.test_capture_archivebox_adapter tests.test_capture_pipeline -v
```

An actual ArchiveBox CLI/API process against a locally served, isolated synthetic HTTPS source is a separate runtime proof requiring provisioned ArchiveBox and a source-use permit. Until both are available, **runtime acceptance is HOLD**: no real source is fetched, no public URL is issued and #171 cannot be closed as a live donor installation.
